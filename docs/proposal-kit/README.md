# Fleetwright proposal kit

These drafts describe implemented work and its measured boundaries. They are portfolio materials,
not client testimonials or claims that an external customer's systems have been automated.

| Need | Draft |
|---|---|
| Authorized crawling and data quality | [Catalogue crawler proposal](crawler-proposal.md) |
| Coordinated browser workers and crash recovery | [Fleet proposal and eight technical answers](fleet-proposal-and-answers.md) |
| Local model assistance across browser tabs | [Local-agent proposal](local-agent-proposal.md) |
| Engineering decisions and verified outcomes | [Public case study](case-study.md) |

Tailor the destination, authorization, acceptance criteria and delivery scope before sending a
proposal. The fleet document contains eight reusable engineering topics; match them to the exact
questions in a client's brief. These files are drafts only and do not record any external submission.

The [release record](../releases/2026-10-13.md), [changelog](../../CHANGELOG.md) and
[measurement notes](../scaling/verification-2026-10-13.md) distinguish deployed releases from local
engineering evidence. No document here promises monthly availability, cloud deployment, arbitrary-site
exactly-once execution or an unmeasured fleet size. Pricing and delivery dates are intentionally absent.

Video production is a separate artifact: these text drafts do not claim that three new capability
videos have been recorded or published. Use verified demonstrations and source evidence, and identify
the actual release/workload shown when attaching media.
