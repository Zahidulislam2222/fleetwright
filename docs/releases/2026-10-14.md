## Corrected behavior

A fresh public freight run exposed a running Python worker without its Playwright driver or
Chromium children: no new booking within 180 seconds, while heartbeat totals still showed four
healthy slots. The original reason for child loss remains unproven. Verified application defects
were missing driver-loss supervision and a heartbeat that treated failed slots as running.

The freight process now uses a bounded read-only Chromium protocol roundtrip and disconnect
callback. Driver/browser loss stops admission, attempts all resource cleanup and exits nonzero for
the existing container supervisor. Successful protocol send/detach share one deadline; a failed
probe proceeds directly to browser disposal. The typed heartbeat interval and action timeout own
cadence and deadline. The CDP method name is fixed protocol syntax. Only ready, connected slots
report running; starting slots appear stale in the API. Ordinary SIGTERM remains a clean drain.

## Retained limits

The initial failed freight shutdown remains a failure; later recovery does not relabel it. The
bounded inspected kernel window and non-OOM container state do not prove the cause of original
driver loss. The original native web image object became unavailable after a preparatory shared-tag
collision. Full native rollback is unavailable; supported rollback is retained old static mounts
using the new trusted web image and compatible backend. Historical incompatible backends remain
forbidden against the durable-detection protocol without a separately reviewed migration path.

The unpatched development-only HIGH `braces` advisory remains disclosed. Prior passive ZAP
inline-style CSP MEDIUM and COEP LOW findings retain their dated 13 October boundary; no new passive
scan is claimed here. Native vulnerability findings describe the exact signed images and scan time.
The separately verified 13 October local-model templates, 50/70-context fixture hours and encrypted
off-host restoration remain historical evidence; no fresh off-host export was performed here.

This is a single-host deployment. No second running site, complete host/key recovery, measured
RPO/RTO, million-user capacity or monthly availability SLA is established by these checks.
