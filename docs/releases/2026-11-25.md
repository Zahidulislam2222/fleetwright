GitHub quality, security and independent uptime workflows passed on that commit. It was live from

This release adds the console **help assistant** (an AI that answers from the published documentation
and the read-only console data the asker can already see), a visitor guide on the owned freight
exchange, machine-readable AI provenance in the local agent, an API-only egress network, Terraform
hub tags and naming, and patched container images. Business runtime behaviour of claims, workers,
workflows and crawls is unchanged.

## What the help assistant does and does not do

- Answers questions about Fleetwright from 16 approved public documents (keyword retrieval) and eight
  read-only tools that run as the asker, inside the asker's tenant. It has no write tools.
- Every answer is disclosed and marked as AI-generated (`ai_generated` in the API,
  `data-ai-generated` in the page). Answers are plain text, never HTML.
- When the AI is off, rate limited, busy, over its daily budget or slow, or when the provider fails (or Redis fails for an anonymous visitor; signed-in sessions themselves need Redis),
  the asker gets the most relevant documentation passages instead.
- Spend is bounded before every paid call: a deployment-wide daily budget reserved atomically at the
  worst-case price and settled to the reported cost, per-user and per-address hourly limits, and one
  whole-answer deadline below the edge proxy's timeout. Nothing the asker types is stored.
- Provider and model: OpenRouter, `anthropic/claude-haiku-5.5`, priced at $0.10 / $0.50 per million
  input / output tokens (provider's public model list, checked 25 November 2026). The deployment's
  daily budget is $0.16 (about $5 a month). See [ADR 0016](../adr/0016-assistant-provider-egress.md).

## Failures found during this release

- **A layout defect reached production for about one hour.** The first deployed candidate showed the
  assistant drawer squashed into the console header with a transparent background: the sticky
  header's `backdrop-filter` made it the containing block of the fixed overlay. Unit and API tests
  could not see it. Fixed by rendering the drawer through a portal; a real-browser regression test now
  checks height, opacity and placement. Recorded in the [defect log](../../DEFECT-LOG.md).
- The same live check showed Markdown symbols in answers and one evaluation case where the assistant
  did not offer the human contact route. The prompt now asks for plain text and always includes the
  maintained contact; the re-run evaluation passed 16/16.
- Two release candidates were rejected before activation because native image scans found new
  advisories; one candidate was rejected because the reused web image was vulnerable.
- After the layout fix was deployed, the GitHub quality workflow failed its dependency audit on
  published Next.js advisories. Next.js was upgraded to 16.4.6, the dashboard rebuilt and the gates
  rerun, and the result was deployed as `20261125-assistant-rc5`; CI then passed.

## Known limits and open items

- One workflow job has been UNKNOWN since 27 October 2026; its reconciliation fails and is retried on
  every loop, which produces frequent warnings. It predates this release and is tracked separately.
- Load-sensitive tests (browser start-up, pacing, timing) fail intermittently on a busy development
  machine; they pass in isolation.
- Single shared server; scale and availability figures elsewhere remain design targets unless marked
  as measured.
